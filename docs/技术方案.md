## 1. 方案概述

### 1.1 一句话技术定位

构建一个**开机即达、单屏无层级、点一下完成**的 Android 桌面替换应用：用 Jetpack Compose 声明式 UI 实现大字 Launcher，用「子女设置模式」完成一次性权限授予与数据预置，长辈使用阶段做到零设置、零弹窗、零后台打扰。

### 1.2 关键结论（先给结论）



| 主题    | 结论                                                 |
| ----- | -------------------------------------------------- |
| 应用形态  | Launcher（HOME 入口，设为默认桌面）+ 普通入口 双形态，单 APK           |
| 架构    | MVVM + 单向数据流（ViewModel + StateFlow + Repository）   |
| 本地存储  | Room（联系人 / 紧急号码）+ DataStore（极简设置）+ 应用私有文件目录（相册）    |
| 预置方式  | 首次安装进入「子女设置模式」：一次性授权 + 导入预置数据，长辈阶段零弹窗              |
| 权限策略  | CALL\_PHONE / SEND\_SMS 在子女设置阶段授予；长辈使用阶段不再出现任何权限弹窗 |
| 天气    | MVP 采用子女侧预置本地数据 + 静默降级展示；不联网、不申请定位（详见 §4-D2）       |
| 最低支持  | minSdk 24（Android 7.0），覆盖低端老年机主流版本                 |
| 风险最大项 | 权限机制与「无权限弹窗」硬约束的调和 → 用设置模式前置解决                     |

### 2.2 依赖注入取舍



* **建议**：MVP 使用 **Hilt**（Google 官方 DI），四个功能模块 + Repository + Room 依赖关系清晰，利于扩展。

## 3. 总体架构

### 3.1 分层与数据流



```
┌─────────────────────────────────────────────────────────────┐

│                        UI 层（Compose）                       │

│   Home  │  Call  │  Family  │  Photo  │  SOS  │  Setup        │

└───────────────┬───────────────────────────────┬──────────────┘

&#x20;               │  StateFlow / UiState          │ 用户事件(Intent)

┌───────────────▼───────────────────────────────▼──────────────┐

│                     ViewModel 层（MVVM）                      │

│   保持 UiState；编排一次性动作（拨号、发短信、切换照片）        │

└───────────────┬───────────────────────────────┬──────────────┘

&#x20;               │                                │

┌───────────────▼────────────────┐  ┌────────────▼──────────────┐

│       Repository 层            │  │    系统能力层（util）       │

│  ContactRepo / PhotoRepo /     │  │  Caller / SmsSender /      │

│  WeatherRepo / SosRepo         │  │  Permissions               │

└───────────────┬────────────────┘  └────────────┬──────────────┘

&#x20;               │                                 │

┌───────────────▼────────────────┐  ┌────────────▼──────────────┐

│      本地存储层                 │  │   Android 系统 API        │

│  Room / DataStore / 文件目录    │  │   ACTION\_CALL / SMS /     │

│  （无服务器、无账号）            │  │   HOME Launcher / 闹钟等   │

└────────────────────────────────┘  └───────────────────────────┘
```



* **单向数据流**：用户动作 → ViewModel 更新 UiState → UI 重组。SOS、拨号等有副作用的动作由 ViewModel 调用系统能力层完成，UI 只负责展示与收集输入。

* **无后台架构**：不注册任何常驻 Service / JobScheduler / WorkManager / 推送。所有功能均由用户「点一下」触发，与产品「无后台打扰」约束严格一致。

### 3.2 双形态（Launcher + 普通入口）



* 单 APK，两个入口 Activity：


  * `LauncherActivity`：AndroidManifest 声明 `MAIN` + `HOME` + `DEFAULT` intent-filter，用户可在系统设置中将其设为默认桌面；开机后系统自动启动它，**无需任何点击**即进入大字桌面。

  * `MainActivity`：普通入口（桌面图标「老年桌面」），进入子女设置模式或普通浏览，用于首次安装配置、后续由子女远程 / 当面维护。

* **HOME 行为**：`LauncherActivity` 使用 `launchMode="singleTask"`，重写 `onNewIntent`，收到 HOME 事件仅刷新 / 回到首页，不做导航到其他 Activity 的越权行为。

* **防回退**：设为默认桌面后，系统 HOME 键始终回到本桌面；不拦截系统返回键的异常行为（避免造成系统级异常）。

### 3.3 关键设计决策（D1–D5）



| 编号 | 冲突 / 空白                          | 决策                                                             | 理由                                              | 需产品确认                    |
| -- | -------------------------------- | -------------------------------------------------------------- | ----------------------------------------------- | ------------------------ |
| D1 | 电话 / 短信需运行时权限，与「无权限弹窗、零设置」冲突     | 引入**子女设置模式**，首次安装一次性授予 `CALL_PHONE` / `SEND_SMS` 并预置数据；长辈阶段零弹窗 | 权限由 Android 强制要求，只能在子女侧前置，无法跳过；这是「不依赖长辈操作」的直接落地 | 是（子女侧是否可接受首启授权流程）        |
| D2 | 首页需显示天气，但约束为无服务器、无账号、无定位权限       | MVP 使用**子女预置的本地天气数据**（展示静态 / 占位），不联网、不申请定位；联网实时天气列后续迭代         | 满足「无权限弹窗、无后台打扰」硬约束；实时天气与定位权限天然冲突，不适合塞进 MVP      | 是（MVP 天气展示为预置 / 占位是否可接受） |
| D3 | 家人模块文案「拨打或视频」与 §6「视频通话暂不接入账号」不一致 | **家人页改为六宫格视频入口**：只显示已配 `wxid` 的家人，点「视频」按钮发起微信视频；拨号移交首页「电话」模块（家人页不再拨打）        | 在「一键微信视频」（功能2）落地后，家人页职责收敛为视频入口；拨号统一由电话模块承担，避免两页重复拨打 | 是（家人页是否接受"仅视频、不拨号"） |
| D4 | 桌面点一下就完成 vs 防误触（尤其 SOS）          | 电话 / 家人 / 照片用「单点 + 大热区」；SOS 用**二次确认 + 倒计时可取消**，兼顾安全与防误触        | 产品要求 SOS「不会误触」，必须牺牲「一键」换取确认                     | 否                        |
| D5 | 低端机流畅                            | 见 §8：启动不做主线程 IO、图片采样、关闭非必要动画、R8、减少重组                           | 满足验收标准「低端机无卡顿」                                  | 否                        |

## 4. 核心模块详细设计

### 4.1 桌面首页（Home / Launcher）

**目标**：开机直达、单屏无滑动、信息醒目、四入口一点进入。



* **布局**（与 demo 原型对齐）：


  * 顶部：大时钟（时：分，秒闪烁）+ 日期 + 天气（`weather.json` 预置值，格式如「晴 28°」）。

  * 中部：四宫格大按钮 —— 电话（绿）/ 家人（橙）/ 照片（蓝）/ SOS（红），每格含图标 + 大字标签，点击热区 ≥ 88dp。

  * 仅一屏、无滑动、无二级菜单。

* **时钟**：用 Compose `LaunchedEffect` 每 30s 校正时间，避免低端机时钟漂移；不使用轮询秒级，降低功耗。

* **天气**：读取预置 `weather.json` 展示；若文件缺失或解析失败，静默隐藏该区块（不报错、不打断）。

* **防误触**：按钮点击热区大、按下有触觉反馈与轻微位移；桌面本身不响应滑动翻页（单屏）。

* **保持亮屏**（可选）：照片 / 首页不设自动休眠策略；如产品需要，可在照片模块短暂唤醒保持亮屏，列入后续迭代，MVP 不强制。

### 4.2 电话模块

**目标**：一个大「拨号」按钮 → 家人通讯录列表 → 点按即拨；**不提供实体拨号盘**。



* 首页「电话」→ 进入拨号页：顶部一个超大「拨号」按钮，下方为家人联系人卡片（头像 + 名字）。

* 点「拨号」按钮：弹出家人通讯录列表（等价于直接展示列表，产品要求「一个拨号大按钮 → 头像 + 名字列表」，此处实现为：点按钮即展开 / 直接呈现列表）。


  * 为与 demo 交互一致，采用**直接呈现联系人列表页**，大按钮作为该页主操作区 / 返回项，避免引入二级跳转。具体呈现以 demo 与评审为准。

* 点联系人卡片 → `Caller.call(context, phone)`：构造 `ACTION_CALL` 意图，授予过 `CALL_PHONE` 则直接拨打。

* **兜底**：若 `ACTION_CALL` 失败（权限被撤、无电话能力），捕获异常并回退到 `ACTION_DIAL`（系统拨号界面），同时给出大字提示；绝不静默崩溃。

* 无实体拨号盘：不在任何界面提供键盘式拨号 UI。

### 4.3 家人模块

**目标**：家人页改为六宫格（3 行 × 2 列，可滚动），作为「一键微信视频」入口；拨号能力移交首页「电话」模块（`CallScreen`），家人页不再承担拨号。

* 数据与电话模块同源（`ContactRepo`），同一份家人通讯录；**只显示已配 `wxid` 的家人**（空格隐藏、整体居中）。

* 六宫格单元：方形大头像 + 姓名 + 微信备注小字 + 绿色「视频」按钮；**仅视频按钮可点**（防误触）。

* 视频按钮门控：`wechatRemark` 非空 && 已校准 && 无障碍已开启（7 步机制；深链已真机判死，不再做 `wxid` 直链替换）。

* 防误触：整格不响应点击，只有视频按钮有热区；按钮增大、保留可感知按下反馈。

### 4.4 照片模块

**目标**：全屏大图轮播，点 / 滑切换。



* 数据：`PhotoStore` 读取应用私有文件目录 `files/preset/photos/`（首启由子女设置模式从 `assets` 拷贝，或子女通过设置模式批量导入）。

* 交互：单指左右滑（`HorizontalPager` 或自研滑动容器）切换上一张 / 下一张；左右各一个大而明显的箭头按钮作为辅助（部分长辈不熟悉滑动手势）。

* 全屏沉浸：隐藏状态栏、点击屏幕不误退；底部圆点指示器显示当前张数。

* 加载：Coil + 采样加载，限制解码尺寸到屏幕大小，避免低端机内存峰值；预取相邻 1 张。

* **边界**：相册为空时显示大字提示「照片还没准备好」，不崩溃。

### 4.5 SOS 模块（关键路径，防误触重点）

**目标**：点两下确认 → 拨打预设号码 + 短信通知家人，绝不误触。



* **状态机**（ViewModel 内实现，可单测）：



```
Idle ──点SOS──▶ Confirm1（大字确认：「要打给儿子吗？」）

Confirm1 ──点「取消」──▶ Idle

Confirm1 ──点「确认」──▶ Countdown（5s 倒计时，大字显示剩余秒数）

Countdown ──点「取消」──▶ Idle

Countdown ──倒计时归零──▶ Triggered（拨打 + 发短信）
```



* **防误触设计**：


  * 二次确认 + 5 秒倒计时，倒计时内可随时取消；

  * 确认 / 取消按钮热区 ≥ 88dp，间距足够大；

  * 触发时伴随强烈振动 + 全屏醒目提示（「已拨打 120 / 已通知家人」），反馈明确。

* **动作**：

1. `Caller.call(紧急号码)`：拨打 `emergency.json` 中的预设号码（如 120 或子女号码）。

2. `SmsSender.send(家人号码, 预设短信内容)`：向紧急联系人列表逐条发送预设求助短信（内容子女在设置模式预置，如「我是 xx，我需要帮助，请尽快联系我」）。

* 短信为**静默发送**（授予过 `SEND_SMS`，直接 `SmsManager.sendTextMessage`），不弹窗、不需要长辈操作。

- **异常兜底**：


  * 拨打失败 → 回退 `ACTION_DIAL` 并提示；

  * 短信发送失败 → 记录日志并大字提示「短信发送失败，请手动联系家人」；不阻塞拨号结果；

  * 任何异常都不允许静默崩溃或白屏。

- **重复触发保护**：触发后进入短暂冷却（如 30s），防止连点重复拨号 / 连发多条短信，同时保证长辈能再次发起（冷却后恢复）。

### 4.6 子女设置模式（Setup，预置与授权）

**目标**：把「依赖子女预置、长辈零操作」落到技术实现上。



* **入口**：首次安装启动（`SharedPreferences`/`DataStore` 判断未初始化）自动进入；后续通过普通入口（桌面图标）可再次进入。

* **流程**（一次性，子女操作，长辈不参与）：

1. 展示引导说明；

2. 一次性授予 `CALL_PHONE`、`SEND_SMS`（系统权限弹窗在此阶段出现，长辈使用阶段不再出现）；

3. 导入预置数据：联系人 / 紧急号码 / 相册（从 `assets` 拷贝或从手机相册挑选）；

4. 写入完成 → 标记「已初始化」→ 提示设为默认桌面（引导跳系统设置，一次完成）。

* **标注**：此模式是 D1 决策的载体，也是唯一允许出现系统权限弹窗的阶段。完成后长辈进入桌面全程零设置、零弹窗。

### 4.7 功能一：家人联系人增删改（电话 / 头像 / 手机号 / 微信备注 / 微信 ID）

**目标**：子女可在设置模式维护家人通讯录（增删改），替代写死的预设数据；长辈只点不编辑。

* **数据**：Room `Contact` 表新增 `wechatRemark`、`wxid`（均可空）列，同时承载手机号 / 头像 / 微信备注 / 微信 ID。

* **入口**：子女设置模式 → 管理家人 → 编辑联系人（`ContactEditScreen`）；支持新增 / 删除 / 编辑，头像可从预设资产选择。

* **校验**：`ContactRules.validateWechatRemark` 保证**微信备注全表唯一**；`ContactRules.validateWxid` 保证**微信 ID（wxid）全表唯一**（空白表示该家人不进入家人页六宫格）。唯一性失败时编辑页给出错误提示，禁止保存。

* **数据迁移**：新增列必须同步升 Room 版本并加迁移（v2→v3 加 `wechatRemark`；v3→v4 加 `wxid`），否则真机旧库校验失败崩溃（见 §5.3）。

* **长辈侧**：电话页 / 家人页按最新名单展示，零操作。

### 4.8 功能二：家人一键微信视频

**目标**：长辈在家人页点「视频」按钮，自动在微信里向指定家人发起视频通话。

**关键背景（真机验证结论，2026-09）**：真实微信屏蔽无障碍节点树（`getRoot().children=0`），且 **微信深链 `weixin://dl/chat|profile?username=wxid` 已逐一验证失效**（Redmi Note 8 / 微信 8.0.76：正例/负例/裸 `weixin://` 全部落到 `MMWebViewUI` 网页壳、从不进入原生聊天 `ChattingUI`，前后台/有无网络均无效）→ **放弃深链，确定采用**坐标手势 `dispatchGesture` + 剪贴板粘贴联系人微信备注 + 微信顶部搜索路径（7 步路线一）。

* **无障碍服务 `WechatVideoCallService`**：
  * 仅开启 `canPerformGestures`（不读窗口内容，最小权限）；
  * `startCall(remark, cal)` 播 7 步时序链：点放大镜 → 写剪贴板 + 长按搜索框 → 点粘贴 → 点搜索结果联系人 → **【等信号】进聊天** → 点右下角「+」→ 点面板「视频通话」→ **【等信号】通话菜单** → 点菜单「视频通话」；
  * **时序策略 = 事件驱动信号 + 延时兜底**（取代纯固定延时）：以微信投递的 `TYPE_WINDOW_STATE_CHANGED`（type=32，带 className+text）为步骤完成信号——等 `ChattingUI`（已进聊天）再点「+」、等 `dialog.a4`+文本含「视频通话」（通话类型菜单）再点菜单「视频通话」；两处信号超时回退按原延时执行；搜索段（放大镜/长按/粘贴/结果）无稳定类名信号，保留固定延时兜底。信号匹配为纯函数 `matchSignal(waitingSignal, cls, text)`，带 JUnit 单测（6 用例）。
  * 全程 try-catch 兜底、30s 总超时、结束恢复剪贴板。

* **校准存储 `WechatCalibrationStore`**（DataStore）：存 7 步相对坐标 + 屏幕物理尺寸（`getRealMetrics`）+ 微信版本；微信版本 / 屏幕尺寸变化时提示重校准。

* **校准向导 `CalibrationScreen` + 悬浮窗 `CalibrationOverlay`**（子女操作）：
  * A1 全手动：悬浮十字光标对准微信内目标按钮并记录；**实际点击点 = 光标中心**（中心带十字准星标识，避免整框误判）；
  * 边录边验：每步单步回放，子女确认是 / 否，可重录上一步；
  * B2 真发验证：第 7 步确认后真正发起呼叫；
  * 悬浮窗为多窗口穿透设计（全屏 UI 层不可触摸 + 光标 / 按钮独立小窗），子女可自由操作微信；
  * **改进（2026-09）**：悬浮窗权限 ON_RESUME 刷新（修授权后按钮卡死）；每步/完成/取消 Toast 反馈；「是(通过)」阶段覆盖 bug 修复；开始校准时自动把家人备注写入剪贴板（否则剪贴板为空、长按输入框无「粘贴」可呼出）；提示条与提示文字降透明度（挡视野）、光标 48dp→28dp。

* **家人页入口**：家人页为六宫格，只显示已配 `wxid` 的家人；当 `wechatRemark` 非空 && 已校准 && 无障碍已开启时，格子显示「视频」按钮 → 调 `startCall`。

* **风险**：依赖微信版本与屏幕坐标（脆弱，更新需重校准）；搜索结果靠备注唯一性规避点错人；wxid 获取门槛（尤其对方改过自定义微信号时需挖原始 ID）。

* **当前状态（2026-09）**：事件驱动服务 + 单测已通过；无障碍已开启；校准尚未完成（子女需在校准向导完成 7 步坐标定位，正在解决第 1/2 步瞄准精度）；完成校准后家人页「视频」按钮显示，即可端到端验证事件门控。

### 4.9 功能三：六宫格桌面 + 导入第三方应用

**目标**：把长辈常用 App（如抖音）放进桌面，点击即可正常使用。

* **桌面形态**：四宫格扩展为**六宫格（3 行 × 2 列）**，第三行两个格子固定用于第三方应用。

* **数据 `AppEntry`**（Room）：`id / packageName / label / order`；**第三方应用上限固定 2 个**，超限拒绝添加。

* **枚举可见性 `<queries>`**：在 Manifest 用 `<queries>` 点名常用应用包名（如 `com.tencent.mm`、抖音），使 `queryIntentActivities` 可枚举到，无需 `QUERY_ALL_PACKAGES`。

* **启动 `AppLauncher`**：`launchApp(packageName)` 用 `ACTION_MAIN + CATEGORY_LAUNCHER` 意图拉起应用。

* **卸载兜底**：应用被卸载后，桌面自动隐藏对应图标，不报错、不留占位。

* **子女管理页 `AppManageScreen`**：白名单勾选 / 添加，写入 `AppEntry`；长辈桌面读取展示。

## 5. 数据设计（本地、无服务器）

### 5.1 存储选型



| 数据           | 载体                            | 说明                                     |
| ------------ | ----------------------------- | -------------------------------------- |
| 家人联系人 / 紧急号码 | Room 数据库                      | 结构化、可增删改；`ContactDao` / `EmergencyDao` |
| 预置状态、少量开关    | DataStore（Preferences）        | 「已初始化」「SOS 冷却时间戳」等                     |
| 相册图片         | 应用私有目录 `files/preset/photos/` | 首启从 assets 拷贝或子女导入；不经媒体库               |
| 天气占位         | assets `preset/weather.json`  | 读取后直接展示                                |

### 5.2 核心数据模型



```
Contact(id, name, phone, avatarFileName, isEmergency, order, wechatRemark, wxid)

EmergencyInfo(id, name, phone, message)          // 紧急号码 + 预设短信内容

PhotoItem(id, fileName, title, order)

Weather(condition, temp)                          // 预置/占位，无实时来源

AppEntry(id, packageName, label, order)           // 功能三：桌面第三方应用（上限 2 个）

WechatCalibration(screenW, screenH, wechatVersion, steps[7])  // 功能二：微信视频校准坐标（DataStore）
```



* **预置流程**：首次进入 Setup → 解析 `assets/preset/contacts.json` / `emergency.json` → 写 Room；拷贝 `assets/preset/photos/` → 私有目录；读取 `weather.json` → 存 DataStore。全部在后台线程（`Dispatchers.IO`）完成，不阻塞首屏渲染；未初始化完成前首页仅显示时钟 + 四个按钮。

## 7. 性能与低端机优化



* **启动优化**：Application 只做轻量初始化（Room/DataStore 懒加载）；首次设置预置在后台线程；首页首帧不依赖任何 IO。

* **图片内存**：Coil 限制解码尺寸至屏幕分辨率、启用内存 + 磁盘缓存、预取相邻 1 张；相册用 LazyList / 分页，避免一次性加载全部大图。

* **Compose 性能**：避免不必要重组（`remember`/`derivedStateOf`）、减少层级嵌套；时钟用 `LaunchedEffect` 低频校正而非秒级重组。

* **动画**：关闭非必要、重型动画；保留轻量按下反馈。

* **构建产物**：R8 混淆、资源收缩、矢量图（图标用 VectorDrawable/Compose 绘制，避免多套位图）。

* **功耗**：无后台轮询、无常驻服务；时钟低频刷新，息屏不跑任务。



***

## 8. 稳定性与安全



* **无后台**：不注册 Service/JobScheduler/WorkManager/ 推送 → 从根本上杜绝后台打扰与耗电。

* **SOS 可靠性**：拨号 / 短信均有 try-catch 兜底与降级路径；触发有冷却防连点；失败有明确大字提示，绝不静默失败。

* **防误触**：大热区、二次确认、倒计时、触觉反馈统一封装在 `Guard.kt`，全局复用。

* **数据安全**：全部本地存储，不联网、不采集、不上传，天然满足隐私诉求。

* **崩溃防护**：关键路径异常统一上报至本地日志文件（`files/logs`），便于子女侧排查；不弹系统崩溃框。

* **权限被撤兜底**：若运行时检测到 `CALL_PHONE` 被撤，电话路径自动降级到 `ACTION_DIAL` 并大字提示，不崩溃。
